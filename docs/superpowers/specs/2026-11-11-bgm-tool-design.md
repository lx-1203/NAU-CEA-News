# 每日 BGM 工具设计

目标：每次制作自动检查 GitHub 音乐组件新版本，只下载当期选中的音频，完成或失败后删除工具拥有的可重新下载临时文件；跨期持久记录使用情况，每轮曲库全部成功使用后重置轮次。

比较方案：整库永久下载简单但持续占空间；每次随机选择占用小但会重复；采用按轮选择、当期临时下载的方案，兼容已发布 ZIP 并优先 HTTP Range 提取单曲，服务器不支持 Range 时在受限临时文件中处理整包。用户原件和已导入的共享曲库不属临时文件。

只增加两个职责明确的模块：bgm_source 校验线上清单并下载指定文件；bgm 负责选择状态、事务、混音和生命周期。标准库 JSON、文件锁和原子替换即可，不新增数据库或后台服务。

状态在配置数据根的 music/history.json，与视频目录分开，更新框架和清理音频均不删除它。身份使用音频 SHA256，改文件名不重置；同一录音按字节去重。按已确认使用集合选择未用音轨，随机打散候选；全用完才开启下一轮，优先避免上一首。新增歌加入当前轮，移除歌不阻止换轮。当前轮、期号到歌曲的绑定及每期成片哈希保存在一份事务状态中。历史 usage 日期可播种，但不把固定开屏主题音乐当每日 BGM。新制作者维护自己的记录，可复制 history.json 迁移；不把个人选曲状态提交到公共仓库。

同一期重新导出沿用原选择，不再占一次；先完成视频校验再提交选曲记录。异常或进程崩溃不计已用，下次可复用待处理选择。互斥文件锁拒绝并发选择；不删除活锁或按时间猜测抢锁。进程级自动释放锁避免崩溃留下永久锁。状态损坏报错而非重建清空历史。日志/清单只有元数据，原音频和下载 ZIP 不按期留存。

下载优先从固定 music-pack-v<version> Release 获取 MUSIC_MANIFEST.json，对照仓库 main 音乐清单只确定当前版本；校验版本、相对文件名、大小、SHA256 和可信下载地址。固定开屏主题排除于每日轮换，轨道可通过 bgm_eligible=false 显式排除。整曲解码通过才参与混音。下载前后均受字节上限约束，任何失败不标记已用。

渲染器在现有音轨上混入低音量 BGM，开屏和栏目静音转场区间保持既有规范；保留无 BGM 主片用于重混，不复制原音乐到每期。只有实际最终视频解码、尺寸、时长、峰值和源码一致检查通过才提交。BGM 来源、署名、哈希、轮次写入当期 bgm-receipt.json，最终归档包含元数据并保护其完整性。

CLI 提供 check/status/prepare/commit/abort/cleanup 与 mix，生产默认自动启用，可明确配置 enabled=false。cleanup 仅处理受工具管理的下载缓存和下载中间文件，默认缓存预算 0；清理发生在上下文退出和下次进入，崩溃残留也被回收。永久删除仅针对本工具创建、可从 GitHub 重新下载的缓存，用户此次明确要求真正释放磁盘空间；不把缓存送回收站继续占盘，不修改既有通用回收站规则。

自检：需求均覆盖；不增加定时自动化；不改每日语音和新闻内容；不给录音重授版权；音乐上传发布仍属隔壁窗口；本功能发布架构与技能 1.3.0，并保持独立音乐版本不变。已有本机四份其他未发布改动保留，不无故纳入本功能。
