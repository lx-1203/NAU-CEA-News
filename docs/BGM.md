# 每期自动选择 BGM

正式 `python -m pipeline.run render ...` 默认自动执行：检查 GitHub 音乐组件 → 选择当前轮未用歌曲 → 下载并核对原始录音 SHA256 → 混音 → 成片检查通过后记录使用 → 删除下载缓存。无需手工找曲、另存一首或下载整库。

## 轮换规则与记录

歌曲身份按音频 SHA256，文件改名不会重新获得一次名额。每轮每份不同录音使用一次，全部用过才开启下一轮；换轮也尽量避免紧接上一首。只有一首时必然重复。新加入歌曲立即进入当前轮；被移除歌曲不阻止换轮。固定开屏 News Theme 不参加每日 BGM 轮换，曲库可用 `bgm_eligible=false` 排除其他音轨。

同一期号重新导出沿用已经选择的歌曲；失败不计入已用，重新运行可以继续原选择。成功记录与最终 MP4 的 SHA256 绑定。原曲单中明确标注的历史刊期只在第一次建立历史时导入。不同音质/不同录音的字节不同，作为不同素材；本工具不声称能识别同名作品的听感重复。

记录存于配置数据根的 `music/history.json`；例如数据根为 `data`，则是 `data/music/history.json`。其中保存当前轮次、当前轮已用 SHA256、每期对应音轨/来源版本/成片哈希和待处理选择。清理音频不删除这份记录，升级程序也不会覆盖它；完整历史仍保留，换轮只重置当前轮已用集合。不要手工清空历史来解决报错，状态损坏会明确停止。

多窗口共用同一数据根时通过操作系统文件锁串行选择和混音，进程退出自动释放；不会按“时间太久”抢锁。不同制作者默认各自维护历史。换电脑或数据根时，在没有制作任务运行的情况下复制整个 `music/history.json`；这不要求保留 MP3。个人使用记录不自动上传到 GitHub。

## 下载与空间

每次制作读取线上曲目清单并核对固定版本 Release 附件。main 已更新而新版还在作为草稿上传时，从 GitHub 公开发布列表选取已发布版本；下次自动再查，不把上传中的文件当成可用曲库。网络或校验失败会停止，不悄悄使用未核实的新文件。

兼容现有独立 ZIP：支持 HTTP Range 时只提取选中曲目；不支持时，临时下载并校验完整 ZIP、提取一首后立即关闭删除 ZIP。单曲上限 128 MiB，整包上限 2 GiB，下载前检查空闲空间。无需 GitHub Token，使用公开附件和发布 Feed。

临时音频只放在数据根 `music/cache/`，工具创建 `OWNER.json` 表明该目录归属。成功、异常和下次启动都会清理工具管理的音频与 `.part`；进程崩溃后的残留在下次使用时清理。缓存预算为 **用后 0 字节音频**，真正删除可重新下载的缓存，不送入回收站继续占用磁盘。清理回执 `music/last-cleanup.json` 保存实际删除字节。

此规则仅适用于本工具创建的下载缓存；用户原件、共享素材库、历史成片、原配音、无 BGM 混音输入、署名与 JSON 记录均保留。既有共享音乐包不会被当成缓存删除；它由曲库发布窗口维护。已有通用视频中间产物仍按项目回收站规则处理。

成片目录保存 `bgm-receipt.json`，含曲名、原始文件信息、SHA256、曲库版本、轮次、署名/权利信息、下载方式、混音和缓存清理回执；最终归档一并保留。无需在每期存一份原曲。若需要重混，从固定版本 Release 重新取得同一 SHA256 的录音即可。

混音保留原画面编码数据，主播音轨不做整体压低；BGM 约 -28 LUFS，并随人声降低音量。固定开屏不叠加新 BGM，栏目独立静音转场按实际时间线逐采样静音。保存 `news-no-bgm.mp4` 作为重混输入。具体效果仍需要制作时试听；自动音量或解码检查不代表人工听感验收。

## 可复用命令

在项目根运行：

```powershell
python scripts/bgm.py check
python scripts/bgm.py status
python scripts/bgm.py cleanup
python scripts/bgm.py mix --date 2026-11-12 --input narration-video.mp4 --output final.mp4 --timeline timeline.json
```

`check` 只更新元数据；`status` 只读本地轮换记录；`mix` 在一个事务中完成自动选曲到清理，要求新输出路径，保留输入。它会在最终视频旁保存 `.bgm.json` 记录。`timeline.json` 使用正式渲染器产出的时间线，必须含真实开屏和独立转场区间；没有这些场景时用 `{}`。

生产配置为 `config/bgm.json`，本机可用 `config/bgm.local.json` 覆盖，明确 `enabled=false` 可关闭正式渲染自动 BGM。框架的配置、源码和技能更新与音乐组件各自版本独立；历史和下载缓存均不属于架构受管文件。

发布接口沿用 `music-pack-v版本` 的 Release，附件包括 `MUSIC_MANIFEST.json`、`NJAU-CEA-Music-Pack-v版本.zip`、`SHA256SUMS-v版本.txt`。曲目 `path` 为安全单文件名，包含 `id/title/path/sha256/bytes`，可选历史使用与权利信息。下载走 GitHub 公共资源，参见 [GitHub 官方附件接口说明](https://docs.github.com/en/rest/releases/assets)。
