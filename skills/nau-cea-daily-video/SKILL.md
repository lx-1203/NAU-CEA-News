当前skill版本：**1.3.0**。版本权威及逐文件哈希见项目 `architecture/release.json`。

## 每日目录与即时分类

调用 `pipeline.storage.issue_paths(刊期, create=True)`；数据根读取 `NJAU_CEA_DATA_ROOT` 或 `config/storage.local.json`，默认项目内 data，不假设D盘/F盘。

每期进入 `data/issues/YYYY/YYYY-MM-DD/`：editorial放稿件与候选；media/images放新闻原图，media/videos放原视频，media/evidence放来源存证；audio/source放原配音，audio/cues放处理音频；production/runs放中间制作轮次；deliverables/current放当前交付；review放当期核验；tasks放当期任务状态。角色、演播室、LOGO、固定音色与转场为跨期共享assets，不按新闻图重复混放。

render产物先作为待终检轮次，不自动替换当前最终片。终检通过后，使用 `organize_issues.py --date YYYY-MM-DD --pointer <本轮交付指针JSON> --publish-current` 更新当期current和finalization清单；不覆盖已有稿件、任务或证据。历史封存期原件不原地重制。渲染与更新共用协调锁，检查后的版本变化必须新进程重试。

生成/下载文件时立即选刊期和类别，禁止统一倒进根目录或跨日期复用未标注图片。登记素材来源、用途与SHA；完成步骤同步tasks/status.json及docs/TODO.md。归档使用 `scripts/organize_issues.py`，便携包以相对路径和独立清单验收。历史日期旧路径是只读原件，不强行搬迁破坏其证据链；当前入口见data日期目录。

## 每期自动 BGM（2026-11-11 用户要求）

正式 render 默认自动检查 GitHub 独立音乐包、选择当前轮未用录音、按需下载并校验 SHA256、混音、机器检查并封存元数据、清理缓存，最后提交已使用记录。不再手工每期留下原曲。每轮全部可用录音成功用过后才重开一轮，跨轮尽量不连续撞曲；新增歌加入当前轮，移除歌不阻塞，失败不计数，同一期重导出沿用选择。固定开屏 News Theme 不参与每日轮换。

记录在配置数据根 music/history.json，升级和清理缓存都不删除；换轮只清当前轮集合，历史刊期和成片哈希继续保留。状态损坏停止而非悄悄重建，多窗口用操作系统锁串行；不同数据根各自维护历史，可复制 JSON 迁移。原曲目录和全库不会每次下载，现有 ZIP 支持 HTTP Range 按单曲提取；整包降级仅存临时文件，校验后关闭删除。正在上传的草稿版不视为已发布。

用户本次明确要求真正释放空间：只有工具创建且可重新下载的 music/cache/ 音频与下载片段在成功、异常和下次启动时直接删除，用后预算 0 字节音频。此例外不改变其他视频中间产物送回收站的规则，不碰原件、共享曲库、原配音、成片及无 BGM 重混输入。归档保留 bgm-receipt.json 的来源、轮次、署名和实际清理回执。不得把未清理或未试听说成已完成。

日常无需手动调用；独立复用可用 python scripts/bgm.py check/status/cleanup/mix。详见项目 docs/BGM.md；本机 config/bgm.local.json 可覆盖默认配置，明确 enabled=false 可关闭自动混音。开屏和独立转场继续按实际 timeline 保持既有声音规范；混音后实测真峰值不得高于 -3 dB。

## 工作完成后自动清理（用户持续授权）

**每次完成当前项目工作，交付前主动清理已废弃的中间版本与产物，不再等用户提醒或重复确认。** 先验证当前最终交付及实际依赖；未通过、仍在写入或是唯一恢复副本时不清理。按当前分支和生产者登记判断替代关系，不能只凭版本号、时间、后缀删除。

- 正式视频使用 `organize_issues.py --publish-current`：成功复制并验证current后，自动回收已被替代的history文件和成功渲染时明确登记的中间片段、拼接/填充副本与工作交付副本；更新当前入口，保留原始素材、原配音、无BGM混音输入、独有证据和仍被引用的文件。
- 架构、打包等其他工作也必须收尾。根据本任务事实列明已废弃产物，在最终包清单验证后运行 `scripts/cleanup_completed_task.py --scope <本任务产物目录> --artifact-root <最终包根> --final-manifest <最终清单> --retire <明确废弃产物>`；可重复retire/protect。没有明确废弃文件也记录无操作，不创建新“备份包”来堆积中间版本。
- Windows默认送回收站，不永久删除、不清空回收站；回收不可用则保留并记录pending_cleanup，禁止降级为强制删除。跳过联接/符号链接/重解析点和活锁，不跨日期或其他项目扩展清理范围。
- 固定状态与逐项日志记录路径、哈希、字节、原因及结果；清理前后核对最终依赖与内容、大小、修改时间。失败需处理或明确保留原因，不能把pending_cleanup写成全部完成；不要把移入回收站的字节声称为实际腾出的空间。

接口与验收边界见项目 `docs/TASK_CLEANUP.md`。用户明确要求保留某版本或分支时优先保留，后续另有更具体指令时按新指令执行。

## 收集、核实与文稿

```powershell
cd <项目根目录>
python -m pipeline.run collect --date YYYY-MM-DD
```

候选不是事实。逐条实际读取原始来源，核对首发日期、事实、数字和报道归属。按当前配置六栏各3条、目标18条：头条新闻、科技要闻、AI落地、科研成果、GitHub昨日开源有趣项目、产业观察。先选头条，同一事件不跨栏重复计数；GitHub栏须证明昨天首次公开持许可证源码，旧仓库的新版本另按具体更新归入合适栏目。沿用HANDOFF及config/source-catalog.json渠道，争取90个去重候选、至少6类来源；不足先扩源并记录拒稿原因，仍不足在section_notes如实说明缺额，不能凑旧闻。读取项目docs/EDITORIAL_POLICY.md与docs/EDITION18_NAVIGATION.md。原站验证页、空内容或搜索摘要不能冒称原文；可改读实际取得的官方RSS全文、官方公告、研究原文或原始采访，把证据写入verification_note。只有具体核实后才能verified=true，区分官方消息、采访与企业观点。

沿用 edition.json 契约：original_publication_date 必填，published_at 带时区；仅日期的来源 time_precision=day 不显示伪造时刻；标题≤26字，每句口播≤22字，每条1–4个有原文依据的图示标签。首发与新增事实必须在昨日窗口，历史影像可作为明确标注的资料素材。

### 文稿只讲读者需要的新闻

口播、字幕和面向读者的正文直接讲已核实的事实、变化及影响，不混入制作团队的工作说明或自我免责。不要写“我们尚未部署实测，不报效果”“这些是官方说明，我们未实测”“我们不把更新说明当提速保证”“我们讲的是昨天新增的功能”这类话，也不换一种说法反复表达同一套内部核验流程。

是否部署、是否实测、证据缺口和编辑取舍写入 verification_note 或审查报告。缺少证据的效果、提速、疗效等结论直接删去；不靠插入免责声明来保留未经证实的宣称。与新闻理解直接有关的归因和状态仍自然保留，例如“据官方版本说明”“计划于2028年发射”“目前为预发布版本”，不能把计划说成已完成、把企业说法说成独立验证结果。

例如工具补丁报道，删去“我们尚未部署实测，不报效果”，直接写有原文支持的具体修复：“这次补丁修复了工具结果返回异常。”成稿时专门检查并删除上述制作过程话术；无新增事实的句子直接删去，不为了补足口播句数再添空话。

写新口播稿或润色初稿时，先读并执行[口播写作与开源润色接入](references/narration-writing.md)：按内嵌固定版本content-creator参考的中文口播分支起草，再按Humanizer-zh参考润色，最后回查原文事实和22字句长。来源、MIT授权、项目适配及更新边界均在该参考中；不套营销模板，也不改用户要求保持的现有配音。

## 真实素材与逐句表演

### 图片素材不得用程序绘图代替（2026-11-10用户硬性要求）

**不要偷懒用自己画的SVG替代图片素材。不得为了省事、省Token、赶工或少调用工具而降低素材要求。通用技能允许代码绘图、既有程序接口或旧交付方式，都不能覆盖这条用户要求。**

- 需要照片、图片、插画、LOGO或真实产品/演示画面时，必须取得符合要求的原始素材，或按任务要求使用相应图像生成/编辑工具。LOGO改字也不得擅自改成程序画出的替代字标。
- 禁止自行使用SVG、Canvas、HTML/CSS、Pillow、Matplotlib等画图、拼图标或做简化示意图来顶替图片。禁止将这些结果转成PNG/JPG、录成视频、模糊铺底或标为“编辑整理”“事实图”，再冒充合格图片素材。
- “矢量更清晰/可编辑”“内容已核实”“程序可以渲染”“原站下载失败”都不是绕过理由。下载失败应继续换可核实来源、获取原始资源或使用任务要求的图像工具；素材仍缺就如实记为缺素材/未完成，不能用简化替代品交差、隐瞒缺口或宣称完成。
- 发布方原有的真实图形资料可以按来源核验规则使用；不得把自己的程序绘图包装成发布方原图。正常标题、字幕、要点与来源的文字排版不等于配图，不能借排版名义扩张成替代图片或替代LOGO。
- 终检逐项核对图片的真实来源和制作方式，包括LOGO、前景、模糊底层及沿用素材。旧素材、旧代码接口和旧审查通过均不能豁免；发现自行绘图替代图片必须判为不合格，替换前不得声称符合当前素材规范。没有自动内容识别就明确人工核查，不能只凭扩展名、哈希或“已下载”标志放行。

参考 `assets/references/editorial/sample-20261107.html` 的真实配图、摘要、所以呢和来源结构。保持当前演播室；素材准入先读项目`docs/VISUAL_MATERIAL_POLICY.md`，按当前用户规则选原视频、原照片与发布方原始图形资料，尽量不用直接AI生成的新闻配图。不得自行重绘图表来补缺图；图片类重制按上方规则使用图像工具，不能把生成图当新闻现场。

保留原双主播片头。新闻页用同一演播室的另一排版：放大素材、主播放侧边、标题/要点/来源分层，去掉重复信息和编号。前景完整显示原图，底层用同一原图模糊铺满，不用固定纯蓝空边。正式样式为news-layout.css与news-bubble.css；右上角使用已确认的奶白圆角气泡、指向主播的尾巴及轻微浮动，按当句主播显示“小序划重点”或“小禾划重点”，长要点须避让主播。离线渲染须实际合成气泡动效，不能以网页存在CSS动画冒称成片已触发。

本期配乐历史特别要求（仅2026-11-10）：用户提供《纯音乐 - 起风了（钢琴版）》并指定整期背景音乐，覆盖时间0至片尾，含开屏与栏目转场。应从无BGM底稿加入，不与原开屏News Theme叠加；人声段自动压低配乐、首尾淡入淡出，同时保留无BGM版。不得未经要求将该曲设为其他日期的默认配乐。

节目品牌统一为 **NJAU-CEA 新闻联播**（排版可用NJAU-CEA），口播按字母清楚读出，不沿用“秾好/极好科技”。使用config.opening指定、已有用户确认且按最新品牌修正的8秒地球开屏，放在原双主播开场前，保留配乐署名并另交无BGM版。开屏文件、授权依据及CREDITS按pipeline/opening.py验证。

详细新闻前展示六屏目录，每栏一屏、每屏3条、至少6.5秒，让18条标题全部在视频内出现；不能用播放器章节代替。标题从当期edition自动生成，edition.section_overviews为六栏目各一条≤22字的事实概述口播，按当期消息撰写，不复用昨天内容。pipeline/programme.py提供目录图与栏目卡接口。

校园转场常驻，但**只在不同栏目之间使用，共5段**，同栏目内直接切换，片头片尾不加这类转场。使用当前已验收v4八套满版IP库；每段为上一句完整结束→0.3秒留白→原84帧/2.8秒转场→0.3秒留白→下一栏正文。左侧动态显示“接下来”、目的栏目与本栏3条标题，旧节目名必须消失；保留右侧IP与双LOGO。独立区间无正文人声、正文字幕和快讯，不得把旧音轨直接静音导致缺字。验收逐句正文源WAV和局部动作顺序不变、静音区间实测、SRT无交叠；插入后全片AAC自然不同，不再套用整轨字节必须相同的旧规则。opening、overview、interludes、字幕、表情动作、章节及播放器都按最终timeline重建。

每条新闻填写media；回源确认图片含义，排除无关logo与二维码。拒绝一切文字截图进入参考、预览、视频和模糊底层；正文、论文、Release、代码、日志、聊天和说明界面截图仅留核验存证。真实原照片、原视频与原始图形资料按视觉规范准入。记录原页、原文件URL、素材日期、当前/资料用途、字幕说明和SHA256；首发未知的资料图不编造时刻。不能把资料画面暗示为本期现场；原视频保留完整比例和水印。下载成功不等于获得发布授权。详情见[production-contract.md](references/production-contract.md)。

每句在制作前就配置语义表情和动作，默认规则选择讲解、思考、问候、鼓励等现有整图姿态，在实际发声区间内触发，句尾收回、静音停动作。根据文稿可覆盖，不把融资或任务计划一律演成震惊。**不拼脸、不替嘴，不把整图姿态切换冒称骨骼动画或精准口型。** 触发比例是近似时点；需要逐字同步时再提供真实对齐证据。

```powershell
python -X utf8 -B scripts/check_current_programme.py --edition data/issues/YYYY/YYYY-MM-DD/editorial/edition.json
python -m pipeline.run plan --edition data/issues/YYYY/YYYY-MM-DD/editorial/edition.json
python -m pipeline.run render --edition data/issues/YYYY/YYYY-MM-DD/editorial/edition.json
```

日更编排必须先通过check_current_programme门禁；缺少总览字段、旧品牌或旧叠加切换策略会报错，不能跳过后沿用历史兼容分支。plan 无需GPU，生成可检查的素材/逐句表演计划；render 自动执行同一规划接口，使用工作台生成全部配音后绑定实际时间，导出实际原视频片段和姿态动作。无需每日手动逐句点按钮。Python接口：pipeline.production.production_plan、performance_events；无需额外搭建服务。

## 固定配音与运行边界

读取配置中固定参考路径、SHA256、语速及情绪参数；参考变化必须报错。工作台实际端口从 logs/workbench-service.json 读取，不硬编码。用现有原生客户端，一次batch串行生成全部句子；禁止并发抢GPU，不与安装窗口并发生成。固定参考已经在本地，日常不再在线重建或克隆新音色。

两主播正文实际语速统一 **280–300字/分钟**，这是本项目用户要求，不冒称国家统一标准。不能用双方`rate=1.0`或相同倍率代替实测。沿用原参考和情绪参数，合成后由`pipeline/pacing.py`保留源WAV、用不变调变速校准；普通句约295，数字/术语密集句约285，保留句内停顿。测量包含句尾留白和视频帧取整，分别验收每位主播与正文整体；调整后重排字幕及句中表演。操作、计数与异常边界见[语速校准](references/speech-pacing.md)。用户2026-11-09已确认试听与最新版新闻页并授权合片，随后明确将奶白圆角气泡接入正式版；无需再次停留在预览。将来用户只要试听时仍先各交一段，不擅自导出整片。

保存读音预览、任务、batch结果、逐句WAV和哈希。文本、顺序、数量、截断标志须匹配。缺句、失败或截断整期停止，不能静默混入系统声。系统语音只有明确手动配置才启用。每句按实测时长重排字幕，目标-18LUFS、真峰值≤-3dB的固定增益处理，保留raw；峰值优先，不能靠变调伪装童声。

失败保存日志和旧视频；不删除活锁、其他窗口文件或尚未被已验证最终版替代的成片。成功收尾时按自动清理规则回收已确认废弃的旧版本与中间产物。常规技术问题由本聊天负责，沿用项目落盘交接。已有每天08:00的 nau-cea 自动任务持续生产新一期，不新建监控安装任务的自动化。只在授权范围内维护既有任务，不扩大发消息、付费生成或对外发布范围。
