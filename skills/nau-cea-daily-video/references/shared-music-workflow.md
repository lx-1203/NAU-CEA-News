# 共享音乐：转换、去重与发布

本文件由唯一项目技能 `nau-cea-daily-video` 引用并随项目发布。它描述流程，不单独授予发布、删除或向其他聊天发消息的权限；沿用用户当前任务和已有授权，不重复逐步确认。

## 入口与版本

- 音乐源目录由当前用户指定，递归包含其子目录；目录名中的文件数可能过时。
- 项目入口为 `architecture/release.json`；现有曲库为 `assets/audio/music/MUSIC_MANIFEST.json`，公开元数据在 `music-pack/`，索引为 `MUSIC_PACK.md`。
- 读实际 `docs/TODO.md`、`docs/SHARED_MUSIC_STATUS.json` 和适用交接记录，认领本任务并保留其他窗口的行。版本与目标仓库以当前配置、线上清单及用户指令为准，不能写死历史曲目数量。
- 先执行主技能要求的在线更新门禁。主目录有其他窗口修改时保留原样，可在干净发布副本通过门禁后处理本任务，不删除活锁或忽略更新冲突。
- 本次工作、大包和下载复验的临时目录由配置或用户选择，并先检查空间。显式指定大文件临时目录，不依赖可能已满的系统 TEMP。不把本机盘符、账号配置或私人目录带入公共包。

## 1. 稳定快照与格式识别

记录每个源文件的相对路径、大小、修改时间及完整 SHA256，区分普通音频、专用格式和下载中的 `.tmp/.part`。处理前后核对稳定性；变化或未下载完成的文件暂缓，记录后再扫，不发布半文件。

不能只信后缀。曾有 `.kgg.flac` 实际仍是加密音乐；已遇酷狗加密头为 `7cd532eb86027f4ba8afa68e0fff9914`。普通 MP3、OGG 等无须因专用格式转换任务而再次压缩。识别失败要保留原件，不用改扩展名冒充转换。

## 2. 解密与 MP3 转换

- 优先使用用户已安装的转换器；本机位置由用户配置或已核实的本地记录取得。无专用格式时可直接进入校验和去重，不要求另装工具或技能。
- 使用 Kugo Music Converter 前读取其当前 README 和请求接口；已有服务先检查 `/api/health`、`/api/config`，新服务绑定回环地址和空闲端口，不结束无关占用进程。
- KGG 的数据库 `KGMusicV3.db` 路径存在不代表含对应歌曲密钥。用户登录酷狗后，可按客户端支持的 `/Open "歌曲路径"` 读取歌曲，再通过 `/api/validate-db-path` 显式重载并重试；以实际解密结果判断。数据库、密钥和登录资料只在本机使用，不上传或写进公共清单。
- 已验证的接口为 multipart POST `/api/convert` 或 `/api/convert-stream`：`inputPaths` 为绝对路径 JSON 数组，另有 `dbPath/outputDir/outputFormat/mp3Quality/concurrency`。先 `outputFormat=copy` 取得解密后的实际音频；质量 `0`、并发 `4` 是既有可用参数，仍须核对目标版本。
- 错误后缀被拒收时，在任务目录复制成真实扩展名后提交；不提前改动源文件。依响应 `input/output` 映射成果，处理不同子目录同名冲突，不猜输出格式。
- 解密后本来就是 MP3 则保留音频字节；其他音频再转 MP3，例如 `ffmpeg -i 输入 -map 0:a:0 -vn -map_metadata 0 -c:a libmp3lame -q:a 0 -id3v2_version 3 -n 输出.mp3`。记录解密复制和有损重编码的区别，保留来源和元数据，不覆盖已有不同内容的同名文件。

## 3. 音频校验与授权替换

逐首完整解码解密结果和最终 MP3，比较实际音频样本时长。既有音乐转换正常差值不超过 0.15 秒；异常必须查明，不能靠放宽阈值掩盖截断。可用 `ffmpeg -v error -xerror -nostdin -i 输入 -map 0:a:0 -vn -progress pipe:1 -f null NUL`。

部分下载 MP3 在 ID3v1 尾部标签处报错。不能忽略错误就放行：确认确为 128 字节 `TAG` 标签，检查音频帧头链及末帧与标签边界，只对临时验证副本排除该标签；验证副本必须严格完整解码，并与原文件完整解码得到的 PCM SHA256 一致。记录边界异常和验证方法，发布文件可继续保留原始字节。不满足条件则保留失败记录，不能把此例外推广到真正损坏的音频。

用户明确选择“成功后替换并删除专用格式原件”时，先把已验证 MP3 写回原目录，确认哈希等于已验证结果，再检查原件哈希未变，最后精确删除这一份原件。Windows 使用 `Remove-Item -LiteralPath`，核对解析后的绝对路径在用户指定根目录内，不递归清空用户目录。失败、冲突和变化时不删；普通音频去重不意味着获准删除源文件。用户要求保留原件时优先保留。

## 4. 去重、来源与权利

- 读取最新已发布曲目清单，核对已有曲目的文件哈希。按完整 SHA256 对本批内部和已有库去重；同名但不同录音或音质的字节不同，应保留，不宣称能识别听感重复。
- 保留已有 track 对象、ID、历史使用、署名、权利和混音参数。新增文件沿用 `track-<SHA256前16位>.<扩展名>`、ID 为 `music-<SHA256前16位>`；前缀碰撞须用完整 SHA 判断并停止覆盖。
- 记录 `id/title/path/sha256/bytes/duration_seconds`、原文件名、来源、加入版本、权利和实际转换记录。`path` 为安全相对单文件名；不把新入库曲目自动设成每日默认配乐。
- 用户提供的作品和录音保留原权利，不给整包套 MIT/CC 许可。已有 News Theme 的署名和 CC BY 4.0 记录继续保留。
- 公共包不含本机绝对路径、私人聊天目录、认证令牌、用户配置、个人选曲历史或酷狗数据库。文本统一 UTF-8 LF。

## 5. 独立组件打包与上传

- 查询远端 releases、main 清单和发布副本状态再定版本。新增音轨递增独立音乐组件 MINOR，元数据修复等用 PATCH；已发布 tag 和包不可覆盖。音乐组件本身变化不自动升级框架；项目技能规则变化则遵循主技能和 `docs/VERSIONING.md` 同步升级框架、技能与更新包。
- 历史构建脚本如绑定旧版本、旧清单和固定数量，不能原样重跑。新一轮使用新的版本工作目录，按真实快照与基线计算总量，保留旧证据和旧发布包。
- 包保持 `NJAU-CEA-Music-Pack-v版本/assets/audio/music/`，含音频、`MUSIC_MANIFEST.json`、README、CREDITS、RIGHTS、CHANGELOG；包根 `PACKAGE_MANIFEST.json` 记录被保护文件的相对路径与 SHA256。ZIP 可用 `ZIP_STORED`，校验 CRC、成员清单、逐文件哈希及路径安全。
- 同步本机共享库、`music-pack/`、`MUSIC_PACK.md` 和专用发布副本。只提交本轮音乐元数据，不把大音频加入普通 Git 历史，不带入其他窗口的修改。按实际空间安排共享库位置，不能为了腾空间破坏现有依赖。
- 按 `global-self-review` 做与范围匹配的审查，确认实际音频、ZIP、元数据、版本、来源、权限范围和公开包隐私检查，再提交和上传。Git 提交身份沿用已核实账号，不擅自修改全局身份。
- 发布 `music-pack-v版本`，附件固定为 `NJAU-CEA-Music-Pack-v版本.zip`、`MUSIC_MANIFEST.json`、`SHA256SUMS-v版本.txt`；使用 `--latest=false`，音乐包不替代框架 latest。多行说明走 `--notes-file`。
- 大文件上传保留进程与 stdout/stderr 日志并跟进至结果。失败先查是否仍在上传及是否留下草稿；草稿缺 ZIP 时只补缺少附件，校对服务端 size/digest/state 后再发布。清单上传不等于整包完成；同一错误不盲目无限重试，也不擅自换仓库或账号。

## 6. 公开复验与收尾

匿名下载完整发布 ZIP，不带认证凭据，验证总字节、整包 SHA256、ZIP CRC、全部成员及逐曲哈希；核对 release 附件、main 和不可变标签清单一致，校验和附件正确。验证下载显式使用空间足够的任务临时目录，结束释放临时文件，不留无意义的第二份大包。

核对源快照未变；期间有新增音乐则补下一稳定快照或记录剩余范围，不能把动态目录全部标为完成。保存本地与公开验证、审查、版本、提交、哈希及来源映射；更新共享状态、交接和自己的待办，保留其他任务。

依主技能已授权的收尾规则回收本次诊断和转换副本，使用通过门禁的 `scripts/cleanup_completed_task.py` 及真实最终清单；保护用户原件、当前共享资产、最终包和唯一证据。失败核对后重试或记待清理，不能把送进回收站的字节当作实际腾出的磁盘空间。

## 消费端：按需使用，不等于手动下载 ZIP

手动点击发布 ZIP 是整包下载。正式自动 BGM 先读取小清单、选取本期录音；服务器支持 HTTP Range 时只从 ZIP 提取这一首，不支持才临时下载并校验整包，提取后删除 ZIP。用后清理工具拥有的下载音频缓存，保留 `music/history.json`、选曲回执、共享库和用户原件。

实际部署和下载方式以目标版本 `docs/BGM.md`、`config/bgm.json`、正式渲染接入和下载回执为准；独立发布副本有代码不代表当前主目录已集成。已验证过从 796236908 字节的包仅下载 2915845 字节取得选中歌曲，未来仍须根据服务端响应保留整包临时回退。
